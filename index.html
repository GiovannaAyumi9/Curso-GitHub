ROLE PARA EXPLORAR
01 / SOBRE O CURSO

Aprender tecnologia
é construir.

O GitHub é uma das ferramentas mais usadas do mundo para organizar projetos e colaborar com outras pessoas — de trabalhos escolares a grandes softwares de código aberto. Neste minicurso você vai entender os conceitos e praticar os principais recursos diretamente pelo navegador.

✳ Sem precisar instalar o Git ou usar o terminal nas atividades principais.
◎

Zero instalação

Todo o conteúdo e as atividades principais funcionam pelo site do GitHub, no navegador do computador ou do celular.

☰

Passo a passo

Cada módulo explica o conceito, mostra o caminho exato dos cliques e termina com dicas para evitar os erros mais comuns.

↻

Progresso salvo

Módulos, checklist e resultado do quiz ficam guardados neste navegador. Pare quando quiser e continue depois.

✦

Projeto de verdade

Ao final você terá um repositório seu, com README, commits e um Pull Request — a base de um portfólio.

Para quem é

  • Estudantes que vão fazer trabalhos em grupo
  • Quem quer começar a programar e montar um portfólio
  • Pessoas de outras áreas que precisam colaborar em projetos
  • Qualquer pessoa curiosa sobre versionamento de arquivos

O que você vai conseguir fazer

  • Criar e organizar um repositório com README
  • Registrar alterações com commits claros
  • Trabalhar com branches sem bagunçar a versão principal
  • Abrir, revisar e integrar um Pull Request
02 / VISÃO GERAL

O caminho de uma mudança.

Quase tudo que você fará no GitHub segue este ciclo. Guarde essa imagem: ela resume o curso inteiro.

  1. 1

    Repositório

    O projeto vive em um repositório, com arquivos e histórico.

  2. 2

    Branch

    Você cria uma linha de trabalho separada para testar ideias.

  3. 3

    Cada alteração é registrada com uma mensagem clara.

  4. 4

    Para gerar o certificado

    0/4
    ⌑
    SEGURANÇA EM PRIMEIRO LUGAR

    Compartilhe seus projetos.
    Proteja seus dados.

    Nunca publique senhas, tokens de acesso ou códigos de autenticação. Antes de tornar um repositório público, revise todos os arquivos e confira se não há informações pessoais.

    01

    Segredos ficam de fora

    Senhas, chaves de API e tokens nunca devem entrar em um commit. Se um segredo vazar, troque-o imediatamente — apagar o arquivo depois não basta, pois o histórico guarda tudo.

    02

    Ative a verificação em duas etapas

    Em Settings → Password and authentication você ativa a autenticação em dois fatores (2FA) e protege sua conta mesmo que a senha seja descoberta.

    03

    Revise antes de publicar

    Antes de deixar um repositório público, abra os arquivos um a um. Procure nomes, telefones, e-mails, endereços e fotos que não deveriam estar ali.

    04

    Use o .gitignore

    Arquivos como .env e pastas de configuração pessoal podem ser listados no .gitignore para que o Git nunca os envie ao repositório.
